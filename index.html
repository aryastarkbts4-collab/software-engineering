BEHIND THE LETTERS · SOFTWARE ENGINEERING

How Little Letters was engineered ♡

Explore the real requirements, architecture, modeling, estimation and tests behind this stationery application.

01 · Requirements & SRS

Functional requirements

  • Compose and customize a letter
  • Select stationery, stamp, envelope and thread
  • Upload up to four movable polaroids and add captions
  • Attach a valid Spotify link
  • Save a local draft, preview and export an HTML letter

Non-functional requirements: responsive layout, readable text, basic input validation, graceful handling of storage limits, and clear feedback.

Requirement identifiers: FR-01 to FR-06; NFR-01 to NFR-05.

03 · Architecture

Current implementation: client-side, event-driven JavaScript application. No server or database is included.

HTML / CSS interface↓ user eventsJavaScript editor & state↓Browser localStorage / asset files↓HTML export & Spotify link

Future extensions could use authenticated accounts and a cloud database, but these are not implemented.

04 · Basic COCOMO Calculator

Estimate development effort from an assumed project size. This is a model, not a measured development result.

05 · Testing Laboratory

Run read-only checks against the current editor and its validation functions. These checks do not change or delete your draft.

Tests have not been run yet.
Tests include required UI elements, stamp assets, Spotify URL validation, photo limit configuration and storage availability.

06 · Iterative Development

Illustrative development phases, not a claim of formal completed Scrum sprints:

  1. Identify family communication needs and define requirements
  2. Prototype the falling leaf and envelope interaction
  3. Implement letter editing, stamps and stationery
  4. Add draggable polaroids and music links
  5. Test, fix defects, and improve sharing

Maintenance: regression-test after each change and keep image paths and styles consistent.
